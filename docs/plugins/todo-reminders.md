# 待办提醒的调度与通知

待办卡片与运行状态保存在本机 `core.db`。前端插件负责编辑和展示，Tauri 主程序负责调度、通知窗口、系统提示音与稍后提醒，因此发布这些变更时需要同时更新主程序和待办插件。

## 到时提醒

- 使用同一套日期匹配逻辑计算每天、每周和指定日期提醒；每周未选择星期不会触发。
- 服务只有一个当前任务；新增、编辑、启用提醒会唤醒检查，禁用插件会立即取消当前任务。
- 最长每 15 秒检查一次。启动或休眠恢复后，只补发当天尚未发送、且设置后到期的提醒；昨天及更早日期不会补发。
- `alarm_firings` 持久化每张卡片最近发送的时间，避免同一次提醒在重复检查、切换插件或重启后再次发送。
- 编辑或重新启用已过时间的提醒，使用下一次有效日期；指定日期全部过期时，需要先编辑日期才能启用。
- 提醒窗口创建失败时尝试系统通知；两种方式都失败时保留重试机会并记录日志。

## 稍后提醒

- `alarm_snoozes` 保存到期时间和原提醒 ID，重启后继续检查；不再为每次稍后提醒创建一个长期休眠的线程。
- 通知窗口 ID 作为请求标识，重复点击或请求重试不会添加重复任务。
- 暂停或删除原提醒会取消关联的稍后提醒；禁用插件会取消全部待发送的稍后提醒。指定日期提醒正常完成后仍可手动选择稍后提醒。
- 当天逾期的稍后提醒会补发；跨午夜保留近 5 分钟的到期任务，避免正常检查间隔误清理。更早日期的过期任务自动清理。
- 新的 `alarmId`、`requestId` 参数为可选，保留旧调用方式。旧调用未传原提醒 ID 时无法关联取消，建议同时更新待办插件与主程序。

## 数据与界面兼容

- 新增运行状态表通过插件存储初始化创建；现有卡片数据保持不变。卸载并清理待办插件数据时一并删除运行状态表。
- 内部星期使用 `Mon` 至 `Sun`，保留旧接口的中文星期响应，更新后的页面独立按当前语言显示。
- `next_alarm_at` 是新增的可选展示字段；前端在旧主程序上会回退到原有倒计时文案。
- 编辑时复制日期与星期数组，保留暂停状态；保存成功才关闭，失败保留输入并显示原因。
- 后台提醒变化通过 `todo-reminders-updated` 刷新页面。隐藏页面暂停定时刷新，重新打开立即读取最新状态。

## 本机验证

1. 新增一分钟后到期的提醒，确认弹窗与系统提示音只出现一次。
2. 编辑暂停的多日期提醒，确认日期与暂停状态保持不变；切换中英文检查星期。
3. 点击稍后提醒后重启应用，确认到期通知仍出现；暂停或删除原提醒后确认待发送任务已取消。
4. 到期前休眠，当天恢复后确认补发一次；再次重启确认不会重复发送。
5. 反复切换页面后操作保存、删除、开关，确认状态及时更新；保存错误时输入仍在。

异常退出恰好发生在系统通知提交与数据库记录之间时，无法保证绝对一次投递；运行中的重复检查和正常重启由持久化记录去重。
