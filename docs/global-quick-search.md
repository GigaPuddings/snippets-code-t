# 全局快速搜索

main 采用已确认的分组单列布局，预览面板沿用原开关和持久化设置。主筛选为全部、功能、设置、内容，应用、书签、文件、工具等放在“更多”。结果分组与键盘索引共用渲染顺序，标题行不占快捷编号。

## 范围与索引

- 页面直接读取 `configNavigationTabs`，设置菜单和搜索共用 `coreSettingsMenuItems` / `getVisibleSettingsMenuItems`，避免维护两份定义。个人中心仍是独立 User 路由。
- “开发者工作台”和设置中的“工作台”分开标明来源。空输入展示近期使用与常用页面入口。菜单支持中英文和固定拼音别名，不索引配置值或密钥。
- 原应用、书签、文件、笔记、片段、工具和网络搜索继续工作。网址和显式引擎快捷语法保持优先级。
- Local AI 注册 `local-ai-conversations`：默认匹配标题，深度检索才查正文；只返回 ID、标题、更新时间、短摘要、匹配分，不传输附件或整个消息树。
- 从原 app.json 构建可重建内存投影，通过文件路径、修改时间、长度检测文件替换。保存、删除、清空对话及停用插件会清除投影并广播 `plugin-search-content-changed`。索引不启动模型，不持久化聊天副本。

## 生命周期与排序

插件必须已安装、已启用并注册成功。宿主注入真实 `plugin_id`；停用或卸载后过滤旧结果、更新查询版本并注销提供者。迟到结果不能恢复已移除的提供者状态。

main 按匹配相关性排序，再参考频率和时效；启动器页的原活跃度排序保留。产品动作跳转成功后才记录历史，历史键包含插件、搜索源、稳定 ID。点击不会立即重排当前列表，新查询/分类/再次检索后应用新历史。键盘进入列表后，异步结果保留所选 ID。

## 跳转和权限

`searchAction` 只接收页面、设置、新建对话、已有对话四类可序列化动作，不接收任意命令或脚本。后端检查字段上限、插件启用状态和 manifest 声明；config 再验证路由/设置归属。插件不可覆盖内置设置或另一插件的设置 ID。

main 先监听回执，再由后端暂存请求并激活 config。config 在冷启动、聚焦及事件到达时读取请求，避免一次性事件丢失。请求有唯一 ID、有效期和回执；失败时恢复 main 与输入，重复点击受执行锁保护。

- “AI 对话”新建空白会话，不发送搜索词；ID 绑定请求并保存，避免组件重挂载重复创建。
- 历史记录按 ID 打开，已删除时提示重新搜索。生成回复期间按现有锁定行为排队并提示，不中断生成。
- 旧 Local AI 包的新建聊天沿用已有原生队列。对话检索和精确记录跳转需要新版 Local AI 包。
- 新 Local AI 包在旧宿主上检查 `context.search.supportsProductActions`，不支持时不注册新搜索源，避免调用不存在的接口。

## 键盘与发布

Enter 打开所选结果；上下键移动；Tab / Shift+Tab 沿用输入、分类、结果切换；Alt+1～9 执行可见项；Esc 关闭。普通数字在输入框正常输入，输入法组合和长按不重复执行。Ctrl+Enter 保留将输入带入新 AI 对话的旧功能。

主程序需要重新构建，Local AI 按原官方插件流程更新。其他插件走兼容路径，不需要全部重新发布；仅构建/检查本次 Local AI 运行时即可。

自动验证涵盖菜单映射、别名、分组/编号、迟到结果、停用过滤、来源归属、冷启动回执、旧包兼容和消息分支索引。实际浅色/深色、系统主题、快捷键、窗口焦点与对话跳转由本地应用手动验收。
